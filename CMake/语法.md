## 流程
1. 设置 **cmake** 版本 
```
cmake_minimum_required(VERSION 3.0)
```
2. 设置项目名称
	- （可选）语言支持类型，比如 C ASM
```
project(项目名)
```
3. 设置输出文件
```
add_executable(app add.c div.c main.c mult.c sub.c)
```


## 变量

set(SRC_LIST add.c  div.c   main.c  mult.c  sub.c)

## 内置变量

### 路径

| 变量名                          | 含义与作用                                                        |
| ---------------------------- | ------------------------------------------------------------ |
| **PROJECT_SOURCE_DIR**       | 最近一次调用 project() 命令的 CMakeLists.txt 所在的源码目录。                 |
| **CMAKE_SOURCE_DIR**         | 整个项目最顶层（最外层）的 CMakeLists.txt 所在的源码目录。                        |
| **PROJECT_BINARY_DIR**       | 最近一次调用 project() 对应的构建（Build）目录。                             |
| **CMAKE_BINARY_DIR**         | 整个项目最顶层的构建（Build）目录（即你运行 cmake -B 后生成的那个总目录）。                |
| **CMAKE_CURRENT_SOURCE_DIR** | 当前正在处理的 CMakeLists.txt 所在的源码目录（在 add_subdirectory 进入子目录时会变）。 |
| **CMAKE_CURRENT_BINARY_DIR** | 当前正在处理的 CMakeLists.txt 对应的构建目录。                              |
### 项目与版本
- **`PROJECT_NAME`**：当前项目的名称（即 `MyProject`）。
- **`PROJECT_VERSION`**：当前项目的完整版本号（即 `1.2.3`）。

### 编译
- - **`CMAKE_BUILD_TYPE`**：控制编译模式。常用值有 `Debug`（带调试信息，不优化）和 `Release`（开启优化，去掉调试信息）。
- **`CMAKE_CXX_STANDARD`**：全局指定 C++ 标准（例如设定为 `17` 或 `20`）。
- **`CMAKE_CXX_STANDARD_REQUIRED`**：设置为 `ON` 时，如果编译器不支持指定的 C++ 标准，CMake 会直接报错停止。
- **`BUILD_SHARED_LIBS`**：全局开关。设置为 `ON` 时，`add_library()` 默认生成动态库（`.so`/`.dll`）；设置为 `OFF`（默认）则生成静态库（`.a`/`.lib`）。
- **`CMAKE_RUNTIME_OUTPUT_DIRECTORY`**：我们在上一个问题里提到的，控制所有可执行文件最终输出的全局目录。
## 命令

### 搜索文件
1. `aux_source_directory` 将文件夹中所有的**源文件名**赋值到**变量**上
```
# aux_source_directory(< dir > < variable >)

aux_source_directory(${CMAKE_CURRENT_SOURCE_DIR}/src SRC_LIST)
```
2. `file(GLOB/GLOB_RECURSE 变量名 要搜索的文件路径和文件类型)`
	- GLOB: 将指定目录下搜索到的满足条件的所有文件名生成一个列表，并将其存储到变量中
	- GLOB_RECURSE：递归搜索指定目录，将搜索到的满足条件的文件名生成一个列表，并将其存储到变量中
```
file(GLOB MAIN_SRC ${CMAKE_CURRENT_SOURCE_DIR}/src/*.cpp)
file(GLOB MAIN_HEAD ${CMAKE_CURRENT_SOURCE_DIR}/include/*.h)
```

### 包含源文件
 - 作用：给一个target 设置它拥有哪些src，这个target是通过 `add_library` 的制作的
```
target_sources(<target>
    <PRIVATE|PUBLIC|INTERFACE> [source1] [source2] ...
    [<PRIVATE|PUBLIC|INTERFACE> [source3] ...]
)
```
- **`<target>`**：必须是已经通过 `add_executable()` 或 `add_library()` 创建好的目标名称。
- **`PRIVATE | PUBLIC | INTERFACE`**：控制源文件的**传递属性**（稍后详解）。
- **`[source1] ...`**：要添加的源文件路径（可以使用相对路径，相对于当前 `CMakeLists.txt` 所在的目录）。

### 生成文件命令

```
# 定义生成文件的命令
add_custom_command(
    OUTPUT "${CMAKE_CURRENT_BINARY_DIR}/generated_code.cpp"
    COMMAND python3 "${CMAKE_CURRENT_SOURCE_DIR}/generate.py" "${CMAKE_CURRENT_BINARY_DIR}/generated_code.cpp"
    DEPENDS "${CMAKE_CURRENT_SOURCE_DIR}/generate.py"
    COMMENT "正在运行 Python 脚本生成源码..."
)

# 2. 自动获取交叉编译器配套的 objcopy 工具路径
set(OBJCOPY ${CMAKE_OBJCOPY})

# 3. 添加自定义生成步骤（编译完成后自动执行）
add_custom_command(
    TARGET my_firmware.elf POST_BUILD
    COMMAND ${OBJCOPY} -O binary 
            $<TARGET_FILE:my_firmware.elf> 
            $<TARGET_FILE_DIR:my_firmware.elf>/$<TARGET_PROPERTY:my_firmware.elf,OUTPUT_NAME>.bin
    COMMENT "正在将 ELF 转换为 BIN 文件..."
)

```


## 链接库
#### 静态库
- `link_libraries(<static lib> [<static lib>...])` 
- `link_directories(<lib path>)`
#### 动态库
```
target_link_libraries(
    <target> 
    <PRIVATE|PUBLIC|INTERFACE> <item>... 
    [<PRIVATE|PUBLIC|INTERFACE> <item>...]...)
```
- target：指定要加载的库的文件的名字
	- 该文件可能是一个源文件
	- 该文件可能是一个动态库/静态库文件
	- 该文件可能是一个可执行文件
- 动态库的链接具有传递性，如果动态库 A 链接了动态库B、C，动态库D链接了动态库A，此时动态库D相当于也链接了动态库B、C，并可以使用动态库B、C中定义的方法。
	- **PUBLIC**：在public后面的库会被Link到前面的target中，并且里面的符号也会被导出，提供给第三方使用
	- **PRIVATE**：在private后面的库仅被link到前面的target中，并且终结掉，第三方不能感知你调了啥库
	- **INTERFACE**：在interface后面引入的库不会被链接到前面的target中，只会导出符号。
