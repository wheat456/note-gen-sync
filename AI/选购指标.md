# AI 

## 计费
- **Input vs. Output 单价**：模型接收输入（提示词、上下文、历史记录）与生成输出（回复内容）分别计价，Output 单价通常是 Input 的 **3 到 5 倍**
- **Prompt Caching（上下文缓存折扣）**：若业务涉及大量固定的 System Prompt 或知识库文档，支持缓存的模型在命中缓存（Cache Hit）时能节省 **50% ~ 90%** 的输入成本。
- **Reasoning / Thinking Token 计费**：针对深度推理模型（如 OpenAI o-series、DeepSeek-R1 等），模型在生成最终答案前的“内部思考过程”也会产生 Token，且通常按昂贵的 Output 单价计费。
- **多模态折算比例**：处理图片、音频、PDF 等文件时，需关注平台如何将文件折算为 Token（例如一张标准图片折算约 200~1000 Tokens 不等）。
## 模型容量与输出规格
- **上下文窗口（Context Window）**：单次请求能容纳的最大 Token 总量（常见规格有 32k、128k、1M、2M）。长文本分析、长对话历史需选大窗口。
- **最大输出长度（Max Output Tokens）**：单次交互模型最多能返回的 Token 数（常见为 4k、8k、16k 或 64k），长文章生成或代码生成任务需重点确认。
## 速率与并发限制
- **TPM (Tokens Per Minute)**：每分钟允许消耗的最大 Token 数，高并发批量处理时最容易触碰此瓶颈。
- **RPM (Requests Per Minute)**：每分钟最大请求次数限制。
- **TTFT（首字延迟）与 TPS（生成速度）**：首字返回时间及每秒生成 Token 数，直接影响实时对话与交互式产品的流畅度。
