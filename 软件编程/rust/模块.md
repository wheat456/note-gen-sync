- `module`对上级封装
- `module`中的内容默认是private对外，不可访问
- `module`同级可以直接访问，但同级的子内容需要权限
- `module`可以嵌套
- `pub(in path)`对`path`进行pub，`path`必须是父级及以上，`pub(self)`在当前`mod`公开，`pub(super)`在父级中公开，`pub(crate)`在当前`crate`可见
- `self`表示当前模块作用域，`super`表示父级`mod`

## 结构体可见性
- 结构体字段默认`private`,不能通过`实例.字段`来访问
- 在`mod`中的`struct`,如果字段是私有的,则不能直接实例化，如果字段是公开的可以实例化
## Use
- 作用：缩小手写的路径
- `use as`可以给一个路径起别名，例如`use a::b::c as func`
- 使用`use`可以在此作用域中屏蔽其他同名的函数
## mod
- mod引用的是顶层文件，例如`test1.rs`，`test2.rs`等
- mod也可引用目录名,但该目录下要有个mod.rs,这就相当于`目录名.rs`
- `pub mod` 二次导出：如果`test1.rs`中有`pub mod test2.rs;`，其他文件只要`mod test1`，就可以`test1`为路径，来访问test2.rs的内容,比如`use test1::test2`
- 层级关系:在一个文件中mod另一个文件，就就代表mod xxx，xxx是这个文件的子模块,main.rs是最高的模块，只能mod等级比自己低的模块，同一个父模块中的子模块可以互相访问
- 如果要mod一个文件夹下的内容
		- 使用mod 文件夹{mod 子文件}

## crate 
- 可执行文件的crate 根是main.rs
- 库的crate 根是lib.rs
	- 在main.rs中通过crate 名来引入lib.rs中的公开函数，不用使用mod
	- lib
		- 在二进制项目中，在toml中没有指定编译类型就默认编译到exe中
		- 在lib中，默认编译为rlib
## 文件分层
- 在`main.rs`中`mod my;`会将`my.rs`或者该名文件夹下的`mod.rs`导入到当前文件中，如果该文件中引入了其他`mod`,那么该`mod`应该是`pub`,否则对于`main.rs`中无法引入


# 新的管理方法

```rust 
text
my_project/
└── src/
    ├── main.rs
    └── my_module/
        ├── sub_module_a.rs
        └── sub_module_b.rs

// 在main.rs中
mod my_module{pub mod sub_module_a.rs}//不用使用mod.rs
```
