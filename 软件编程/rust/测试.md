## 代码测试
- `#[cfg(test)]`,只要在`cargo test`时才编译mod`tests`
- 用法：
```rust
#[cfg(test)]
mod test{
	#[test]
	fn it_works(){
		assert_eq!(1+1,2);
	}
}//assert_eq!("{}",a),可以输出格式化信息
```
- 测试`panic`,使用`#[should_panic]`测试`panic`出现`panic`则通过
```rust
#[should_panic(expected = "Guess value must be less than or equal to 100")]
//使用expected的来指定具体panic
panic!( "Guess value must be less than or equal to 100, got {}.", value);
//expected和panic中的字符串前缀相同即可
```
- 测试`Result`
```rust
#[cfg(test)]
mod tests {
    #[test]
    fn it_works() -> Result<(), String> {
        if 2 + 2 == 4 {
            Ok(())
        } else {
            Err(String::from("two plus two does not equal four"))
        }
    }
}

```
- 测试流程
	- `$ cargo test -- --test-threads=1,单线程测试
	- 如果要显示测试中的`println!`,`$ cargo test -- --show-output'
		- 默认测试失败会显示，测试成功不显示println!的内容
	- 如果运行单个测试则`cargo test 测试函数名`
		- 也可以是函数名的一部分
	- 自定义测试个数`cargo test 测试的共同字符串/mod 名`
	- `#[ignore]`忽视某个测试用例
	- `cargo test tests -- --ignore`运行被忽略的测试
		- 也就是被ignore标记的测试函数
- 单元测试
	- 和正常代码写在同一位置
- 集成测试
	- `cargo test --test  某个文件` 测试tests文件下的单个文件
	- 在src同级目录下新建一个tests目录，其目录下是测试用例
	- 在tests目录下新建`common`目录用于创建公共代码，公用的测试函数
		- 作为rs的文件，会被当成测试文件
		- 作为目录时不会被测试，并将其他文件记录在mod.rs中
		- 被测试的函数仍然需要#\[test]
	- 当文件名命名为`mod`时，其名也可以是目录名
- Result：测试函数的返回值
	- 返回`ok()`的内容就算测试通过
	- 返回`Err()`就算测试失败
## 断言
- `assert!`,`assert_eq!`,`assert_ne!`在所有模式下运行
- `debug_assert!`,`debug_assert_eq!`,`debug_assert_ne!`在`debug`中运行
- `assert_eq!`
	- 判断2个值是否相等，不相等直接`panic`
	- 要实现比较则，2个表达式须实现`PartialEq`，`Debug`
- `assert_ne!`与`assert_eq!`相反
- `assert!`判断传入的布尔值是否为`true`,不为true就panic
- `assert!(表达式,提示信息，值)`

## 测试
- 测试的代码也可以像正常的代码一样有`mod`,并且可以标注为`#[cfg(test)]`，在`cargo test`下才有效，被标记`#[test]`的函数不该有输入，每个测试函数就是一个测试单元，在测试单元中调用其他函数，并测试返回来判断这个测试单元测试的内容是否合格
