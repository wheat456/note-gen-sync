Subject（`Subject`、`BehaviorSubject`、`ReplaySubject`、`AsyncSubject`）

| **Subject 类型**              | **核心特性** | **订阅后会收到什么？**                        |
| --------------------------- | -------- | ------------------------------------ |
| **`Subject<T>`** 📢         | 纯粹的中继器   | 订阅**之后**发出的所有数据。                     |
| **`BehaviorSubject<T>`** 📍 | 状态持有者    | **最新**的一个数据（如果没有则发初始值），以及后续数据。       |
| **`ReplaySubject<T>`** 🎞️  | 历史放映机    | 订阅**之前**的所有（或指定数量）历史数据，以及后续数据。       |
| **`AsyncSubject<T>`** 🏁    | 最终结果派发   | 只有在 `OnCompleted` 之后，才会收到**最后一个**数据。 |

### 1. `Subject<T>`：最简单的“直播” 📢

它是最基础的实现。它不保存任何历史，错过了就是错过了。

- **场景**：处理实时事件，比如点击按钮、收到即时消息。
    
- **特点**：只有在订阅那一刻起，后面产生的数据你才能看到。
    

### 2. `BehaviorSubject<T>`：最新的“状态” 📍

它要求你必须给一个**初始值**。每当有新观众进入直播间，它会立刻告诉观众“当前最新的状态是什么”。

- **场景**：保存配置信息、当前用户状态、开关状态。
    
- **特点**：订阅时立刻获得“当前值”。
- 就是还没有发送数据的时候，如果有人订阅了就发送默认值
    

### 3. `ReplaySubject<T>`：带回放的“录像” 🎞️

它可以缓存历史数据。你可以设置缓存的时间窗口或者缓存的数量。

- **场景**：确保新订阅者不会错过重要的初始化序列或之前的关键日志。
    
- **特点**：不管你什么时候来，都能“回看”之前的精彩片段。

在 Rx.NET 中，你可以这样定义它：

- `new ReplaySubject<int>()`：记录**所有**历史。
    
- `new ReplaySubject<int>(2)`：只记录最近的 **2 条**历史。
    
- `new ReplaySubject<int>(TimeSpan.FromSeconds(10))`：只记录最近 **10 秒内**发生的事。
    

### 4. `AsyncSubject<T>`：只要“结局” 🏁

它非常冷酷，不到最后不开口。只有当流彻底结束（`OnCompleted`）时，它才把最后一个值发给所有订阅者。

- **场景**：类似于任务（Task），只关心最终计算结果。
    
- **特点**：在没完成之前，订阅者什么也拿不到。


### 🎬 场景回放

1. Subject 发出 `1` 
2. Subject 发出 `2`
3. **新订阅者（New Observer）加入** 4. Subject 发出 `3`

|**如果它是...**|**订阅者收到的序列**|**理由**|
|---|---|---|
|**`Subject`**|`[3]`|它是冷酷的转播员，之前的 `1` 和 `2` 已经错过了。|
|**`BehaviorSubject`**|`[2, 3]`|订阅瞬间拿到**当前最新**的 `2`，然后紧跟后续的 `3`。|
|**`ReplaySubject`**|`[1, 2, 3]`|它像录像机一样，把**所有历史**（`1` 和 `2`）都回放了一遍。|
|**`AsyncSubject`**|`[3]` (需等待)|只有在调用 `OnCompleted()` 后，它才会吐出**最后一个**数字 `3`。|

使用 `.AsObservable()` 将其“降级”为只读的 `IObservable<T>`。
```cs
private readonly Subject<string> _lightningSubject = new Subject<string>(); // 外部只能订阅，不能乱发数据 
public IObservable<string> LightningAlerts => _lightningSubject.AsObservable();
```
