# 结构形模式

## 装饰器模式
- 在每一个函数中可以去调用基类中同样的函数

1. 有两个角色，一个是`被装饰对象`，另一个是`装饰器`
2. `被装饰对象`继承一个`基类/接口`
```cs
interface IBasic{
 void func1(){
 }
 void func2(){
 }
....
}



class BasicClass:IBasic{
	//实现接口中的方法
}
```
3. `装饰器基类`也同样实现其`接口`，但是内部还要添加一个`字段`，类型为继承的`接口/基类`
```cs
abstract class BasicDecorator(IBasic BeDecoratedClass) :IBasic{
	//实现接口,并表明虚方法
	...
	
	// 声明一个接口类型的字段
	IBasic BeDecoratedClass;

}

```
4. 实际装饰器继承装饰器基类，并重写装饰器基类中的虚方法
```cs
Class ConcreteDecorator(IBasic xxx):BasicDecorator(xxx){
	// 从写方法
	
	//
	IBasic BeDecoratedClass=xxx;
}

```
5. 最终，可以实例化一个`装饰器`，并填入需要`被装饰的类`，同样也可以填入`装饰器`
```cs


IBaisc Aa= new ConcreteDecorator(new BasicClass){}

```

## 代理模式


- 目的：给目标对象添加一层代理，用于限制对其的访问
- 不同代理的区别是，各种代理的职责不同

1. 创建一个`接口/类`，`代理`和`真实对象`都继承这个
2. 其中`代理`持有一个`真实对象`的字段
3. 可以在代理的操作方法中添加一些行为，从而实现各种功能，在访问真实对象之前

```cs
interface Subject{
	void Operation(){
	
	}
}
class proxy:Subject{
	RealSubject _realsubject;
	void Operation(){
	}
}

class RealSubject:Subject{
	void Operation(){
	
	}
}

```

## 组合模式

- **目的**：让客户端对“单个对象”（叶子）和“对象容器”（组合）的使用具有**一致性**
	- 也就是说调用单个对象使用的方法于调用组合种的的方法都是一样的，不过组合是递归的调用集合种的方法
- 在组合模式中有两种角色，一种是`叶子`也就是说它没有持有`叶子集合`，另一种是`组合`，也就是说它持有`叶子集合`或者`组合集合`
- 无论是`叶子`还是`组合`都继承同一个`基类`，拥有同一种操作方法，但是`组合`还拥有`添加`和`移除`等操作`集合`的方法

```cs
abstract class BaseClass{
	// 操作方法，这个方法对于叶子和组合都有,都应该实现
	abstract void Operation(){
	
	}
	
	//组合才有这个方法，用于操作集合
	virsual void add(){
	
	}
}

//创建一个叶子类型，没有集合
class leaf:BaseClass{
	void Operation(){
	
	}
}

class composite:BaseClass{
	
	// 这里代表这个集合既可以装叶子，也可以装自身类型
	list<BaseClass> 
	

	void Operation(){
		//这里可以遍历集合，调用他们的操作方法
	}
	// 添加集合方法
	override void add(){
	
	} 
	
	
}

```
