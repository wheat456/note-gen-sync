# 行为设计模式

## 中介者模式
1. 顾名思义，需要一个`中介者`，该`中介者`需要持有`需要通知的对象`，同时提供一个`方法`给`客户`调用，`客户`通过这个`方法`来告知`中介者`相关的事情
```cs
Class Mediator{
	// 假如这里有2个客户
	Client client1;
	Client client2;
	
	// 这是一个通知方法，但是由客户来调用的，意思是客户想要通知中介者什么
	// 当然可以命名为“来之客户的消息”这个函数，其中p1 代表着是哪一个客户，以及p2代表着想要传达的东西
	void Notify(p1，p2){
		// 在这里可以拿到客户传递的东西，可以进行一些操作，比如去通知另一个客户，通过调用它暴露的接口
	}
	// 在构造中给客户设置中介者
	Mediator(client1,client2){
		client1.setxx
		client2.setxx
	}
	
}
```

2. `客户`需要持有`中介者`引用，并提供一个设置`中介者`的`方法`，可能会想直接通过构造传入中介者就可以，但是从代码可读上面，还是让中介者调用设置方法，这样中介者知道需要去通知那些客户。`客户`也应该提供一些方法给`中介者`，以便`中介者`接受其他`客户`的消息时，能知道如何通知这个`客户`

```cs
class Client{
	Mediator med;
	
	//设置中介者的方法
	void SetMed(){
	}
	// 这个函数是提供给中介者的，意思是让中介者在想要告诉我什么时，就调用这个方法
	void OtherWantTellMe(){
	}
	
	// 这里可以调用中介者的通知函数，去告诉中介者一些事情
	void Operation(){
		med.Notify()
	}

}
```

3.  实例化
```cs

Client client1 = new();
Client client2 =new();
Mediator med = new(client1,client2);

// 这里去告诉中介者一些事情，同理client1也调用该方法去告诉中介者
client2.Operation()


```

## 状态模式
- 有两个角色，一个是状态，一个是对象
- 对象
	- 首先一个对象拥有改变状态的方法
	- 持有状态字段
	- 拥有一些对外暴露的行为，但是对外暴露的行为实际上是取决于状态的，也就是具体是由状态去实现到底要干什么
	
- 状态可以通过持有对象来改变状态，状态中的方法是实际上在该状态下会执行的特定的逻辑


1. 创建一个类，拥有一个为`状态`的字段，同时这个类也应该有一些行为方法
```cs
// 假如创建一个“Person”的类
Class Person{
	// 拥有一个状态的字段
	State state;
	
	// 各种行为方法,里面通过状态去调用
	void eat(){
		state.HandleEate(this);
	}
	
	void sleep(){
		state.HandleSleep(this);
	}
	
	// 切换状态的方法
	void SetState(State state){
		_state=state
	}
	
}
```

2. 创建`状态`的基类，同时拥有在该状态下处理各种行为的方法
```cs
interface IBaseState{
//持有人的本身，方便拿到一些上下文信息
	void HandleEat(Person person){
		
	}
	void HandleSleep(Person person){
	
	}
	
}

```
3. 创建真正的状态，继承至状态基类
```cs
// 假如有两个状态，分别是正常状态和生病状态

class NormState:IBaseState{
	// 实现接口中的方法，定义自己的逻辑
	void HandleEat(Person person){
		//吃的多，然后生病了
		person.SetSate(new SickState())
		
	}
	void HandleSleep(Person person){
		//着凉了，然后生病了
		person.SetSate(new SickState())
	}
	

}

class SickState:IBaseState{
	// 实现接口中的方法，定义自己的逻辑
	void HandleEat(Person person){
		//吃的多，大补，然后好了
		person.SetSate(new NormState())
		
	}
	void HandleSleep(Person person){
		//睡一觉，然后好了
		person.SetSate(new NormState())
	}

}

```

2. `被装饰对象`继承一个`基类/接口`
```cs
interface IBasic{
 void func1(){

 }
....
}

	//实现接口中的方法
}
```
3. `装饰器基类`也同样实现其`接口`，但是内部还要添加一个`字段`，类型为继承的`接口/基类`

```cs
abstract class BasicDecorator(IBasic BeDecoratedClass) :IBasic{
```

```cs
interface Subject{

	}

```

## 组合模式

- **目的**：让客户端对“单个对象”（叶子）和“对象容器”（组合）的使用具有**一致性**
	- 也就是说调用单个对象使用的方法于调用组合种的的方法都是一样的，不过组合是递归的调用集合种的方法
- 在组合模式中有两种角色，一种是`叶子`也就是说它没有持有`叶子集合`，另一种是`组合`，也就是说它持有`叶子集合`或者`组合集合`
- 无论是`叶子`还是`组合`都继承同一个`基类`，拥有同一种操作方法，但是`组合`还拥有`添加`和`移除`等操作`集合`的方法

```cs
	virsual void add(){
	
	}
}

//创建一个叶子类型，没有集合
class leaf:BaseClass{
	void Operation(){
	
	}
}

class composite:BaseClass{
	
	// 这里代表这个集合既可以装叶子，也可以装自身类型
	list<BaseClass> 
	

	void Operation(){
		//这里可以遍历集合，调用他们的操作方法
	}
	// 添加集合方法
	override void add(){
	
	} 
	
	
}
```
