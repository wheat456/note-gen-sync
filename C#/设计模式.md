# 行为设计模式

## 中介者模式
1. 顾名思义，需要一个`中介者`，该`中介者`需要持有`需要通知的对象`，同时提供一个`方法`给`客户`调用，`客户`通过这个`方法`来告知`中介者`相关的事情
```cs
Class Mediator{
	// 假如这里有2个客户
	Client client1;
	Client client2;
	
	// 这是一个通知方法，但是由客户来调用的，意思是客户想要通知中介者什么
	// 当然可以命名为“来之客户的消息”这个函数，其中p1 代表着是哪一个客户，以及p2代表着想要传达的东西
	void Notify(p1，p2){
		// 在这里可以拿到客户传递的东西，可以进行一些操作，比如去通知另一个客户，通过调用它暴露的接口
	}
	// 在构造中给客户设置中介者
	Mediator(client1,client2){
		client1.setxx
		client2.setxx
	}
	
}
```

2. `客户`需要持有`中介者`引用，并提供一个设置`中介者`的`方法`，可能会想直接通过构造传入中介者就可以，但是从代码可读上面，还是让中介者调用设置方法，这样中介者知道需要去通知那些客户。`客户`也应该提供一些方法给`中介者`，以便`中介者`接受其他`客户`的消息时，能知道如何通知这个`客户`

```cs
class Client{
	Mediator med;
	
	//设置中介者的方法
	void SetMed(){
	}
	// 这个函数是提供给中介者的，意思是让中介者在想要告诉我什么时，就调用这个方法
	void OtherWantTellMe(){
	}
	
	// 这里可以调用中介者的通知函数，去告诉中介者一些事情
	void Operation(){
		med.Notify()
	}

}
```

3.  实例化
```cs

Client client1 = new();
Client client2 =new();
Mediator med = new(client1,client2);

// 这里去告诉中介者一些事情，同理client1也调用该方法去告诉中介者
client2.Operation()


```

## 责任链模式
1. 首先，构建一个处理系统，这个系统拥有第一个持有第一个处理者的引用，然后提供一种方法来构建一条责任链
```cs
Class ResSystem{
	// 第一个处理者
	Hander _handler1;
	ResSystem(){
	 _handler1=new Handler1()
	 // 设置第一个处理者的下一个处理者是谁
	 _handler1.setSuccessor(Handler2)
	 Handler2.setSuccessor(Handler3)
	 
	}
	
	// 处理函数
	
	void handle(){
		_handler1.handle();
	}
	
}
```
2. 创建处理者，拥有一个后继者字段
```cs
Class Hander1{
	// Handler是接口或基类的类型

		// 如果没有后继者就直接返回
		
		//如果能处理就返回结果
	}
	
	// 设置后继者的方法
	void setSuccessor(){
	
	}

```

1. 首先，拥有一个系统，该系统拥有一个策略字段，和设置策略方法，以及执行方法
```cs
Class System{
	Strategy _stratedy
	
	void set(xxxx){
	
	}

	}
}



```

2. 设置`策略接口`，所有`策略`都实现它，但是每个`策略`中的`excute方法`中的逻辑确实不同的

```cs
interface Strategy{
	void excute();
}

Class StrategyA{

	void excute(){
	
	}
}

Class StrategyB{
	void Excute(){
	
	}
}

```

3. 使用
```cs
// 系统设置一种策略，并执行这个策略

system.set(StrategyA)


// 实际上是调用里面的策略的执行方法
```

## 状态模式
- 有两个角色，一个是状态，一个是对象
- 对象
	- 首先一个对象拥有改变状态的方法
	- 持有状态字段
	- 拥有一些对外暴露的行为，但是对外暴露的行为实际上是取决于状态的，也就是具体是由状态去实现到底要干什么
	
- 状态可以通过持有对象来改变状态，状态中的方法是实际上在该状态下会执行的特定的逻辑


1. 创建一个类，拥有一个为`状态`的字段，同时这个类也应该有一些行为方法
```cs
// 假如创建一个“Person”的类
Class Person{
	// 拥有一个状态的字段
	State state;
	
	// 各种行为方法,里面通过状态去调用
	void eat(){
		state.HandleEate(this);
	}
	
	void sleep(){
		state.HandleSleep(this);
	}
	
	// 切换状态的方法
	void SetState(State state){
		_state=state
	}
	
}
```

2. 创建`状态`的基类，同时拥有在该状态下处理各种行为的方法
```cs
interface IBaseState{
//持有人的本身，方便拿到一些上下文信息
	void HandleEat(Person person){
		
	}
	void HandleSleep(Person person){
	
	}
	
}

```
3. 创建真正的状态，继承至状态基类
```cs
// 假如有两个状态，分别是正常状态和生病状态

class NormState:IBaseState{
	// 实现接口中的方法，定义自己的逻辑
	void HandleEat(Person person){
		//吃的多，然后生病了
		person.SetSate(new SickState())
		
	}
	void HandleSleep(Person person){
		//着凉了，然后生病了
		person.SetSate(new SickState())
	}
	

}

class SickState:IBaseState{
	// 实现接口中的方法，定义自己的逻辑
	void HandleEat(Person person){
		//吃的多，大补，然后好了
		person.SetSate(new NormState())
		
	}
	void HandleSleep(Person person){
		//睡一觉，然后好了
		person.SetSate(new NormState())
	}

}

```
